# 从 v1.1 升级到 v1.2

## 一句话

**直接覆盖即可。** 不用卸载重装，不用动 dsh 运行时，不用动你的实例数据。

---

## 升级步骤

### 1. 关闭 PCL
正常关窗即可 —— 它会自动停掉 dsh 服务。

> ⚠️ 如果你之前是**强制结束** PCL 的（任务管理器结束进程 / 关机未正常退出），
> 先确认任务管理器里没有残留的 `node.exe`。
> 有的话结束掉，否则端口会被占着，新版启动会失败。

### 2. 解压新包，覆盖旧文件
把 `PCL_DSH_v1.2_*.zip` 解压到**原位置**，覆盖同名文件。

需要替换的文件：

```
Plain Craft Launcher 2.exe
Plain Craft Launcher 2.exe.config
Plain Craft Launcher 2.xml
PCLCS.dll
MeloongCore.dll
MeloongCore.Wpf.dll
Microsoft.Win32.Registry.dll
LICENCE
```

**你自己的数据目录不要动** —— 它不在这个文件夹里。

### 3. 确认数据目录位置
数据目录由注册表决定：

```powershell
# 查看当前数据目录
Get-ItemProperty "HKCU:\Software\PCLDebug" -Name DshDataRoot
```

默认是 `%TEMP%\PCL\dsh\`，但如果你改过（比如迁到别的盘），
升级**不会**碰它，继续用原来的位置。

> 💡 也可以把新包解压到**全新目录**（更干净），
> 首次启动后在「设置 → 启动 → 维护与修复」里把数据目录指向原位置即可。

### 4. 启动新版本

## 版本兼容性

| 项目 | 是否需要处理 |
|---|---|
| **dsh 运行时**（Node / pnpm / dsh 本体） | ❌ 不用动，继续用现有的 |
| **你的实例数据**（对话历史 / API Key / 插件） | ❌ 不用动，格式没变 |
| **数据目录位置** | ❌ 不用动 |
| **实例清单 `instances.json`** | ✅ 向下兼容（`version: 1` 未变） |
| **快照格式** | ✅ 向下兼容（`manifest.json` 的 `version: 1` 未变） |
| **设置项** | ✅ 新增了几个，旧设置自动沿用 |

**依赖变化**：**没有新增任何依赖**。仍然是 .NET Framework 4.8 + 原有的几个 dll。

### ⚠️ 唯一需要留意的一点

如果你有**旧版创建的快照**，它们**仍然可以正常恢复**，
但**删除**时 v1.1 会失败（报「程序权限不足」，见下）。
升级到 v1.2 后就能正常删除了 —— 这也是本次升级的主要目的之一。

## 这次升级修了什么

### ① 删除快照报「程序权限不足」，以管理员运行也没用 ← 主要修复

**根因和报错信息说的完全不是一回事。**

那个报错路径是 `attachments\v1\objects\32\322d8562...`，是**附件对象文件**。
dsh 的附件是**内容寻址存储**，写完就设 **`ReadOnly` 属性**防篡改。
而 `Directory.Delete(path, True)` 遇到只读文件会直接抛
`UnauthorizedAccessException` —— **它不会帮你清属性**。

> ⚠️ 所以这**不是权限问题，是文件属性问题**。
> 报错里那句「以管理员身份运行」**根本没有用**。

**修法**：新增健壮删除（先试常规 → 失败则逐层「清 `ReadOnly` → 删文件 →
删空目录」→ 遇到符号链接只删链接本身），并**把全项目 16 处危险删除全部替换**。

### ② 启动超时后进程泄漏

「等待 dsh 就绪」有 3 分钟超时。原来超时时直接抛异常，**什么都不清理**：
dsh 进程还在跑、还占着端口、事件处理器还挂着，而界面已显示"失败"。
再点一次启动就撞端口冲突。

**修法**：把清理逻辑抽成 `CleanupProcess`，超时路径也调用。

### ③ 全量导入带不过来聊天记录

dsh 的对话正文存在 `$DSH_HOME/sessions/`，而原清单里只有 `storages/`（索引）
→ 导入后「索引在、正文不在」：列表能看到会话，点开是空的。

**修法**：`sessions` 加进清单（8 项 → 14 项）；并把数据收集**提到插件解析之前**
（原来 `package.json` 缺失就会提前返回，全量导入会**静默地什么都不搬**）。

### ④ 不再凭空生成 `.minecraft`

一个声称「不含 MC」的软件每次启动都在自己目录里造一个 `.minecraft`。
上游 PCL 的逻辑在扫不到 MC 文件夹时会兜底创建，剥离 MC 时没动这段。

**修法**：开头早退（只加判断、不删上游代码，避免上游合并冲突）。

### ⑤ 快照恢复缺路径越界检查

恢复时遍历快照目录的条目写进实例目录，但**没校验条目名** ——
而快照目录是用户可以手工改的。

**修法**：加条目名白名单 + 目标路径二次确认。

### ⑥ 插件安装网络超时时界面「装死」

进度浮层只显示「正在安装…」，用户以为程序死了强制结束 PCL，留下半装环境。

**修法**：进度透传（显示「网络不稳，正在重试……**（可以继续等，不用关掉 PCL）**」）；
超时 10 分钟 → **30 分钟**；网络类失败时**主动建议换源**。

### ⑦ 其他

- **原子写入共用固定临时文件名**（9 处）→ 两线程同时写会静默数据错乱 → 加随机后缀
- **密钥验证是死代码**且硬编码官方地址 → 接进界面，保存 Key 后自动验一次
- **内存泄漏**：`HashSet(Of ProcessStartInfo)` 强引用永不移除 → 改用弱引用表
- **体积统计跟随符号链接**导致虚高 → 3 处统一

## v1.2 新增的两个功能

### 对话历史跨实例复制

每个实例的对话历史是**独立的**。可以选一个实例当来源，
把它有、其他实例没有的会话复制过去。

**只补缺** —— 目标已有的会话**一个都不会被改动**。

> 实例1 有 `{1,2,3,4}`、实例2 有 `{4,5,6,7}` → 复制后是 `{1,2,3,4,5,6,7}`，
> 实例2 原有的 4/5/6/7 原样保留（**不是**覆盖成 `{1,2,3,4}`）。

入口：**设置 → 启动 → 维护与修复 → 对话历史**

### 插件配置跨实例复制

把实例 A 调好的插件组合搬到实例 B。入口：
**设置 → 启动 → 维护与修复 → 插件配置**

---

## 关于「每个实例独立」

**这点很重要，很多人会以为多个实例共享同一份数据 —— 不是的。**

| 项目 | 说明 |
|---|---|
| 对话历史 | 各自一套 |
| API Key | 各自一套（可以给不同实例配不同网关） |
| 插件 | 各自一套 |
| 配置 | 各自一套 |

**共用的只有 dsh 运行时**，所以开多个实例不会重复占用几个 G 的磁盘。

想集中对话用「对话历史」复制，想搬插件用「插件配置」复制。
