# 从 v1.2 升级到 v1.3

## 怎么升级

把 `PCL_DSH_v1.3_*.zip` 解压到**原位置**，覆盖同名文件即可。

数据目录（`runtime\`、`instances\`、`snapshots\` 等）**不受影响**，不需要备份。
如果你自己改过 `settings.json`，覆盖前留意一下 —— 安装包不含它。

---

## 本次新增

### 1. 多版本并存：可以同时装多个 dsh 版本

**以前的问题**：装另一个版本会**就地覆盖**同一个目录，旧版本直接没了 ——
想"先试试新版、不满意再切回来"根本做不到。

**现在**：每个版本装进自己的目录，可以随时切换。

```
runtime\
  dsh\                    ← 旧的单例目录（保留，老用户的运行时还在这里）
  versions\
    0.1.6-alpha.2\        ← 每个版本一个目录
    0.1.7-alpha.1\
```

在「下载 → 镜像版本 → 运行时」里能看到所有版本，各有「切换到它」按钮。

**装完不会自动切换** —— 你装新版通常是为了试，不是立刻换掉正在用的那个。

**切换时会提醒插件兼容性**：

> ⚠ 切换运行时可能影响已装的插件。
> 你目前共装了 22 个插件（分布在 2 个实例里）。
> 插件是按 dsh 的内部接口写的。如果新版本改动了这些接口，
> 部分插件可能报错或失效 —— 这不是插件坏了，是版本不匹配。
> 建议：切换前先给实例拍一个快照。

（刻意不做"精确的兼容性判定" —— 插件生态里没有统一的兼容性元数据，
硬判会产生大量误报。提醒 + 让你自己决定，比假装能判断更诚实。）

**老用户不受影响**：`runtime\dsh\` 那个旧目录被当作一个普通槽位保留，
升级后照常能用。

### 2. 导出环境：把整个环境打包带走

「下载 → 镜像版本 → **导出环境…**」

四类内容可以任意勾选：

| 内容 | 说明 |
|---|---|
| **运行时** | Node + dsh 本体（**默认不勾**，见下） |
| **插件** | 依赖清单 + 本地插件目录 |
| **对话历史** | 会话正文 + 索引 + 附件 |
| **用户配置** | API Key + 设置 + profile 配置（**默认不勾**） |

导出的包是标准 zip，可以直接分享给别人，或者搬到另一台机器。

**两个刻意的默认值**：

- **运行时不默认勾** —— 它有几十万个文件（约 3.8 GB），复制要十几分钟。
  而运行时是**通用**的，别人自己装配即可；真正需要搬的是插件、对话和配置
  （约几百 MB，几十秒就能导完）。
- **用户配置不默认勾** —— 导出是把数据交到**别人**手里，含密钥的默认值必须保守。

勾上「用户配置」后会**再确认一次**，并提供「剔除密钥」选项：
保留配置结构（有哪些接入方式、BaseUrl、模型名），但把密钥值留空。
别人导入后填自己的 Key 就能用 —— **「分享配置」不等于「分享密钥」**。

### 3. 导入环境：导出的包能导回来了

「下载 → 镜像版本 → **导入运行时…**」选包即可。

导入时会自动认出包的类型：

- **纯运行时包** → 走原来的流程，装成一个运行时槽位
- **导出环境包** → 显示包里的内容清单，让你选**导到哪个实例**，然后：
  - `runtime\` → 装成一个**新的**运行时槽位（不影响现有的）
  - `home\` → 插件 / 对话历史 / 用户配置 写进目标实例

> ⚠️ 实例数据会**覆盖**目标实例的同名文件（同名会话记录、同名插件配置）。
> 导入前建议先给目标实例拍一个快照，万一不满意可以回滚。

**注意**：不含运行时的导出包也能导入了（以前会被直接拒收）。

### 4. 自定义网关：不再强制要求 `sk-` 前缀

**以前的问题**：填自建网关 / 中转服务的 Key 时，会被
「DeepSeek 的 API Key 通常以 sk- 开头」拦下来 —— 但人家本来就不长这样。

**现在**：

- **DeepSeek 官方** —— 仍然要求 `sk-` 前缀（能提前发现粘贴错误）
- **自定义网关** —— 只做最小校验（长度 ≥ 8、不含空白字符），什么格式都收

**配套的安全改动（重要）**：日志脱敏原来**只认 `sk-` 开头的密钥**，
放开格式后，自定义网关的密钥会**明文出现在日志里**，而「AI 分析日志」
会把日志发给 DeepSeek —— 相当于把密钥交出去了。

现在改成**两层**：

1. **已知值精确替换**（主力）—— 从凭据文件读出你实际保存的密钥做替换，
   不靠猜前缀，零漏网
2. **正则兜底** —— 扩展了 `sk_` / `key-` / `api-` / `token-` 等变体，
   以及长 hex 串（很多自建网关用这种）

### 5. 「检查更新」现在会明确告诉你该不该更新

以前点完只是把版本号塞在明细里，看不出重点。现在版本号下面会有一行
**带底色的状态**：

| 情况 | 显示 |
|---|---|
| 有新版本 | 🟡 **发现新版本：0.1.7-alpha.1（预发布）—— 当前是 0.1.6-alpha.2，建议更新** |
| 已是最新 | 🟢 **已是最新版本（0.1.6-alpha.2）** |
| 还没装 | 🔵 **未安装 dsh —— 建议安装 x.x.x** |
| 比通道目标更新 | 🟢 **当前版本比通道目标更新 —— 无需操作** |

版本比较用 semver 解析（不是字符串），所以 `0.1.10 > 0.1.9` 判断正确。

### 6. 导出/导入有实时进度了

导出和导入都会显示**两行**：

- 第一行：阶段 + 百分比（`正在复制（123456/396782）（45%）`）
- 第二行：具体在做什么（当前文件名）

带节流（120ms），所以界面不会被高频刷新卡住。

## 修掉的缺陷

### 保存对话框的路径问题（v1.2 的 bug）

v1.2 里导出时会弹**「打开」**对话框（按钮写着「打开」而不是「保存」）——
因为用错了 API（`SelectFile` 是"选一个已存在的文件"，导出该用 `SaveFile`）。

而且保存后文件**不落在你选的位置** —— 会跑到桌面或程序目录里。
根因是我加的一段"路径补全"逻辑把用户的选择覆盖了。

现在：对话框标题「选择导出位置」、按钮「保存」、文件名预填，
并且**记住你上次选的目录**，下次从这里开始。

### 「下载」菜单报 `Dir` 函数错误

`Dir` 是 VB 的内置函数。我改代码时把循环变量从 `dir` 改名成 `dirPath`，
但漏改了两处引用 → `dir` 被解析成**调用内置 `Dir()` 函数** →
「必须先用 PathName 参数调用 Dir 函数」→ 整个下载页加载失败。

已修复，并扫过全项目确认没有同类遗漏。

### 导出卡死

我一度加过一个"跟随符号链接统计体积"的函数。pnpm 的 `node_modules` 里有
**大量断链**（指向被裁剪的子包），跟随遍历会不断抛异常 + 写日志，
异常开销远大于正常遍历 —— 实测把程序拖死。

已删除该函数，并给所有大目录遍历加了**日志节流**（同类错误只记前几条，
之后汇总报一次），避免任何遍历把日志刷爆。

### 体积统计口径

顺带澄清一个曾经搞错的点：pnpm 的 `node_modules` 里
**真实文件 37858 个 / 668 MB**，另有 **6721 个目录链接但不占空间**。
所以"复制出去要多少字节"= 真实文件总量 = 668 MB —— 这是对的。
（我曾用 `followlinks=True` 算出 3.8 GB，那是**重复计数**。）

## 已知限制

- **运行时是所有实例共用的**，不能给不同实例指定不同版本或不同镜像源。
  每个实例独立的是**数据**（对话、插件、密钥、配置）。
  要做"每实例绑定运行时版本"需要架构级改动，暂未实现。
- **切换 dsh 版本可能导致插件失效** —— 插件是按内部接口写的，
  上游改接口时第三方插件通常滞后。切换前建议拍快照。
- **导出包不含 node_modules 的软链接结构**（重建为等价链接），
  跨机器导入时如果目标机器缺 Node，会用 PCL 自带的 Node 启动。

## v1.3.1 补丁（同日发布）

v1.3 发布后实测发现：**用导入的运行时启动会报「目录名称无效」**，
体检误报「dsh 安装不完整」，一键修复又自动切换到新装的版本。

根因是**三处代码写死了旧的单例目录** `runtime\dsh\` ——
多版本并存后运行时装在 `versions\` 或 `imported\` 下，
那个旧目录可能根本不存在。

已修：

| 位置 | 修法 |
|---|---|
| 启动工作目录 | 从入口脚本反推运行目录（`DshDeriveWorkDir`），并校验存在性 |
| 体检 | 从激活槽位反推；并修正「导入的运行时没有 .pnpm 属正常」 |
| 一键修复 | 清理**激活槽位**的 node_modules；装完**切回原槽位** |

如果你已经装了 v1.3 并且用的是导入的运行时，**建议升级到 v1.3.1**。
